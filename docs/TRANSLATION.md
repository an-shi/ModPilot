# 汉化系统

## 三级策略

### 第一级：搜索现有汉化包

`TranslationEngine.find_packs()` 同时查询：

- Nexus Mods GraphQL（名称/关键词、游戏 domain）
- GitHub 公开仓库搜索

匹配依据包括：原 Mod 名称、UniqueID、Nexus Mod ID、汉化关键词。结果会给出“较可能匹配 / 可能相关 / 低置信度”的提示和匹配原因，但**不宣称已验证兼容**。候选按分数排序并保存。

为什么不能自动应用远程包：

1. Nexus API 下载链接受账号权限限制；ModPilot 不绕过 Premium。
2. 名称匹配不能证明版本兼容。
3. 汉化包可能包含恶意或错误结构。

因此 UI 提供“打开页面”和“导入已下载汉化包”，导入时会执行键名与占位符校验。

### 第二级：本地翻译缓存

`translation_cache` 按：

```text
game_key + target_language + sha256(source_text)
```

保存译文。任何用户/模型翻译过的相同原文都可复用；人工确认的译文会标记 `confirmed`，并在缓存命中时优先作为人工译文使用。缓存不包含 API Key。

### 第三级：AI 翻译

仅对以下条目触发：

- 没有现有译文，且
- 没有可用缓存，或用户强制重新翻译

使用 OpenAI 兼容 `/chat/completions`。请求包含：

- 系统提示：只翻译值、保持键、保持占位符、返回 JSON
- 待翻译 JSON 对象
- 严格 JSON 模式（可关闭以适配本地模型）

翻译结果逐条校验，失败批次最多重试一次；仍失败的条目在数据库中标记 `failed`，不会写入目标文件。

## 星露谷 i18n 机制

适配器识别：

- `i18n/default.json`（优先）
- `i18n/en.json`
- 写入 `i18n/zh.json`

要求：

- 不改写 `default.json` / `en.json`
- 写入前备份整个 `i18n` 目录
- 先校验再原子写入
- 保留 JSON 对象结构与 UTF-8 编码
- 已有 `zh.json` 的无关键会保留
- 如果写失败，自动从备份恢复

## 占位符与格式保护

`core/text_tokens.py` 会保护：

| 形式 | 示例 | 说明 |
|---|---|---|
| SMAPI 双花括号 | `{{name}}` | 翻译变量 |
| 花括号参数 | `{0}` | 格式化参数 |
| printf | `%s` `%d` | 格式参数 |
| 转义换行/制表 | `\n` `\t` | 文本布局 |
| 星露谷插入符 | `^` | 对话换行/控制 |
| 美元变量 | `$var` | 文本宏 |
| 尖括号标签 | `<color=red>` | 富文本标签 |
| 玩家名标记 | `@` | 游戏文本占位 |

实现方式：

1. 提取所有 token，长 token 优先，避免 `{{name}}` 被拆成 `{name}`。
2. 用私有区 sentinel `\uE000N\uE001` 替换。
3. 发送给模型；提示中要求原样保留 sentinel。
4. 恢复 sentinel，按多重集校验 token 数量与内容。
5. 任何缺失、增加、残留 sentinel 都视为失败，不写入。

这比“翻译后简单 replace”更安全，能发现模型重复/遗漏占位符。

## 人工编辑

翻译编辑页显示：

- Key、原文、译文
- 状态（待翻译/已翻译/已确认/失败）
- 来源（AI/本地缓存/人工/已有汉化）
- 模型、更新时间、确认标记

操作：

- 保存译文（人工编辑，未确认）
- 保存并确认（写入人工缓存，供其他用户/Mod 复用）
- 重新 AI 翻译（可覆盖，会要求确认已确认条目）
- 应用已保存译文
- 导出 JSON
- 移除生成的目标文件（不影响原始 Mod 文件）

## 校验与回滚

写入前：

1. `adapter.validate_translation`: 键存在、占位符、空值、非字符串。
2. `TranslationEngine._write_target`: 备份 i18n 目录。
3. 适配器原子写入 `zh.json`。
4. 失败则从备份恢复，抛出可读错误。

导入汉化包：

1. 解压到暂存目录（防路径穿越）。
2. 寻找 `i18n/zh.json` / `zh-cn.json`。
3. 只取源文件存在的键；未知键忽略并警告。
4. 占位符与结构校验。
5. 备份并写入。
6. UI 明确提示“无法自动证明版本兼容”。
