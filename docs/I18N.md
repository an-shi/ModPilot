# 界面多语言（i18n）

ModPilot 默认选中的界面语言是**简体中文**（`zh-CN`），同时内置完整英文语言包（`en-US`）。语言选择保存在本地配置中，入口为“设置 → 更新与外观 → 界面语言”。

## 设计

本地化使用轻量运行时目录，而不是编译 `.qm` 文件：

```text
modpilot/i18n.py                  tr()、语言切换、语言列表
modpilot/locales/zh_CN.json       简体中文翻译目录
modpilot/locales/en_US.json       English translation catalog
```

源码中不写任何用户可见的界面文案，而是使用稳定的消息 ID：

```python
from modpilot.i18n import tr

label = tr("ui.pages.settings.settings")
message = tr(
    "ui.pages.downloads.retrieved_0_files_nexus_api_remaining_quota_1",
    count,
    remaining,
)
```

每个语言目录都是完整映射，`zh_CN.json` 和 `en_US.json` 的键集合必须一致：

```json
{
  "language": "zh-CN",
  "name": "简体中文",
  "translations": {
    "ui.pages.settings.settings": "设置",
    "ui.pages.downloads.retrieved_0_files_nexus_api_remaining_quota_1": "已获取 {0} 个文件。Nexus API 剩余额度：{1}"
  }
}
```

`tr()` 支持 `str.format` 占位符和 `%s`/`%d`。带参数的 f-string 已改为“模板 + 参数”的形式，避免先格式化后无法匹配翻译。若当前语言缺少某个键，`tr()` 只回退到英文目录，最后返回消息 ID；不会隐式显示中文。`tr_or()` 用于适配器显示名等需要业务兜底值的场景。

## 默认语言与切换

- `AppConfig.ui_language` 默认 `zh-CN`，因此首次启动时下拉框默认选中“简体中文”。
- 语言设置立即保存。为了避免后台任务、已构造的窗口和半翻译状态互相冲突，**完整界面在下次启动 ModPilot 时应用**；设置页会明确提示。
- 启动时，`app.py` 先读取配置并加载对应目录，再导入 UI 模块，保证页面标题和所有控件使用正确语言。

## 不翻译的内容

- 产品名、平台名和协议名：ModPilot、Nexus Mods、SMAPI、GitHub、Windows、API、JSON 等。
- 用户/Mod 提供的内容：Mod 名称、作者、描述、日志原文、文件路径、错误堆栈。
- 配置值、UniqueID、Nexus Mod ID、文件名。

## 添加新语言

1. 在 `modpilot/i18n.py` 的 `SUPPORTED_LANGUAGES` 增加语言代码与显示名；同时把新代码加入 `modpilot/config.py` 中 `AppConfig.ui_language` 的类型约束。
2. 新建 `modpilot/locales/<code>.json`，从 `zh_CN.json` 或 `en_US.json` 复制全部键并翻译值。
3. 保持所有 `{}` 占位符、`%s`/`%d`、`\n`/`\t` 与其他目录一致。
4. 运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_i18n.py -q
.\.venv\Scripts\python.exe -m pytest -q
```

`tests/test_i18n.py` 会扫描 `modpilot/` 中所有 `tr()` 消息 ID，检查两个目录的键集合、占位符一致性、英文目录是否残留中文，以及源码中是否重新出现硬编码中文界面文案。缺失键会在测试中失败。

## 已知限制

- 切换语言需要重启应用后完整生效。
- 原始日志、Mod 描述、AI 模型输出等外部内容保持原文，不做机器翻译。
- 翻译目录随应用本地提供，不需要网络或云端服务。
